# Motion UI 提示词整理与测量

日期：2026-10-14。版本保持 0.7.0；本轮不发布。基线：main add0a96，已发布构建 0.7.0+6adc22f63978；本轮测量构建：0.7.0+45277dc37fec。

## 组织方式

- 引导模式：3 段非空系统提示——通用设计与当前风格、共享接口契约、2 个短案例。
- 自由模式：1 段非空系统提示——表达选择与接口契约；另外 2 个已注册段返回空文本，不注入风格或案例。
- 工具保持 9 个：4 个生成入口、目录、校验、检查、局部修正、结构更新。
- 完整组件字段、画布程序与动效案例按需查询；新增 text/native/style 主题。画布默认仅给场景摘要，指定 scene 才取一个完整案例。
- 共享契约只出现一次；去除 Host 追加的重复指南。风格负责配色、材质与构图，通用层负责信息质量，不规定统一视觉外壳。
- 吸收 Taste Skill 的内容优先、层级、实质简洁和真实观察原则；未整体导入网站营销流程、随机构图、强制图片或全局审美禁令。

## 复现

运行 `node scripts/audit-prompts.mjs test-output/prompt-audit/current.json`。设置 `MOTION_TOKENIZER_MODULE` 为 js-tiktoken 的可导入路径，可获得参考 token；未设置时仍能统计字符、段数和工具数。脚本通过实际 apply 注册并解析 Host 文本，不扫描源码字符串猜数量，不添加插件运行时依赖。

本轮 before.json/after.json 和各项运行日志保存在忽略目录 test-output/prompt-audit；此报告保留汇总结果。

## 验证与实际限制

119 项单元/集成测试通过。完整回归覆盖 23 组检查；最终复查中原生样式场景曾在保存后刷新等待上超时，单独复跑通过，其余后续动效、机制和复制组也通过。没有因此修改生产渲染器或放宽断言。

Desktop/Web 各 196 个打包文件哈希与仓库一致；运行状态页确认实际 Host/Client 构建一致、资源正常、纠错钩子和原生侧栏接入。测试使用 1920×1080 桌面视口及「测试结果」工作区。

MiniMax-M3.1-Flash-Preview High 的实际请求核对：引导模式三段原文到达模型；自由模式一段原文到达模型、没有选定风格或引导案例；九个 Motion UI 工具在本次选用 Agent 中均可见。沿用现有 High 和 provider 默认输出配置，未新增推理/输出/时间限制，未取消生成。

| 场景 | 实际交付 | 工具失败 | 观察 |
|---|---|---|---|
| 简短 GitHub 五步流程 | render_text → render_text | 1（最终复测；前一轮为 0） | 模型给 code 多填 copyable，移除后成功；无需用户点名 UI，实际显示流程 |
| 假设旅行预算 | render_ui → native 目录 → render_ui | 1 | 首次漏写 chart.rows，查阅后补交；3 人 6000 元，5 人 3 间房、9400 元；Web/Desktop 实际操作与刷新恢复通过 |
| 齿轮原理 | render_mechanism + render_canvas + render_text | 0 | 同轮三块 UI；约 196 秒，自然完成 |
| 自由月相 SVG 动画 | render_canvas | 0 | 约 233 秒，自然完成；不注入风格，定位到 180° 后暂停、显示 100% 照明比例，操作恢复原值；局部标题对比度偏弱 |

精简不会保证模型首次调用正确、快速或每次设计优秀。早期探索轮还出现 flow 预设误填 layout、漏 nodes、expr 数字及 String()、把边界放 slider 上等问题；已用简短的字段说明明确这些边界。最终预算和流程案例各有一次模型字段补交；代码块自带复制按钮，模型仍可能误填仅供 text 的 copyable。保留这些真实结果，不把「最终有界面」等同于「无重试」或「设计质量全部过关」。

原生状态操作后恢复了测试前数值；模型测试结束恢复原设计模式和风格。版本保持 0.7.0，未提交发布或上传 npm。
